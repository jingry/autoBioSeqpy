UBPs‑MFCPred
==================

UBPs‑MFCPred: A multimodal deep learning framework for accurate and interpretable prediction of ubiquinone-binding proteins
==================

Corresponding Author
==================
ljs@swmu.edu.cn

 Overview
==================
UBPs‑MFCPred is a deep learning–based computational framework for the identification of ubiquitin-binding proteins (UBPs). It integrates traditional fixed encodings (OneHot, DC, CTriad, PAAComp) and high-quality embeddings from pretrained protein language models (ProtT5, ESM‑1b, ESM2, Ankh) with a hybrid neural network architecture. Specifically, protein sequences are encoded through both engineered descriptors and PLM embeddings, which are then processed by a combination of convolutional, dense, and extractive fusion layers to capture discriminative signals associated with UBPs. The framework is systematically evaluated on 127 feature combinations using 5‑fold cross‑validation and independent testing, achieving an accuracy of 0.9122 and an MCC of 0.8253 in cross‑validation, with robust generalization on a held‑out test set. By effectively combining multimodal feature encoding and deep learning, UBPs‑MFCPred enables accurate, interpretable, and scalable prediction of UBPs across diverse proteomic datasets.

All datasets used in this study are included in the "UBPs‑MFCPred/data" folder. The folder is organized as follows:
• Training data (train) – Contains files for model training constructed from the curated UBPs dataset:
    • 2 protein sequence files for training positive and negative samples (potr.txt, netr.txt), consisting of 450 UBPs and 450 non-UBPs
    • Multiple protein language model (PLM) feature files (potr_*.txt, netr_*.txt), including representations generated by ESM-1b, ESM2, ProtT5, and Ankh
    • Multiple traditional feature files (potr_*.txt, netr_*.txt), including CTriad, DC (Dipeptide Composition), and PAAComp (Physicochemical Property) encodings
• Test data (test) – Contains the test set used for model evaluation:
    • 2 protein sequence files for test positive and negative samples (pote.txt, nete.txt), consisting of 74 UBPs and 74 non-UBPs
    • Corresponding PLM feature files (pote_*.txt, nete_*.txt) with the same feature types as the training set.
    • Corresponding traditional feature files (pote_*.txt, nete_*.txt) for CTriad, DC, and PAAComp

File naming convention:
• potr.txt – training set positive sample sequences
• netr.txt – training set negative sample sequences
• pote.txt – test set positive sample sequences
• nete.txt – test set negative sample sequences
• *_ESM-1b.txt, *_ESM2.txt, *_ProtT5.txt, *_Ankh.txt – feature files generated by different PLMs
• *_CTriad.txt, *_DC.txt, *_PAAComp.txt – feature files generated by traditional encoding methods
• Other feature files follow the same pattern, representing different PLM features.
All datasets include protein sequences and derived feature representations necessary for model training and final evaluation.


Model
==================
Neural network model availability

All neural network models used in this study are included in the "model" folder. Two distinct architectures are provided, depending on the feature representation.

• CNN architecture
The CNN model is defined in `CNN.py`. It consists of a single convolutional layer with 250 filters and a kernel size of 11, followed by global max pooling, a dense layer with 128 units and ReLU activation, and finally a sigmoid output layer for binary classification.

For traditional features (CTriad, DC, PAAComp), the three feature vectors are first concatenated into a 20000‑dimensional vector, which is then reshaped into a 2D matrix of shape `(1000, 20)` before being fed into the convolutional layer. For PLM embeddings (ESM‑1b, ESM2, ProtT5), the input is a matrix of shape `(sequence_length, embedding_dimension)`, and the reshaping step is adjusted or omitted accordingly.

This architecture was selected after systematically exploring different kernel sizes (3, 7, 11, 15) and filter numbers (50, 150, 250). The final configuration (250 filters, kernel 11) achieved the best performance across validation sets.

• DNN architecture
For Ankh embeddings (768‑dimensional), a deep neural network defined in `Ankh.py` is used. It consists of two fully connected hidden layers with 384 and 192 units, respectively, both using ReLU activation. A dropout layer with a rate of 0.2 is added after the first hidden layer to reduce overfitting. The output layer uses sigmoid activation.

All models were trained on the curated UBPs dataset and used for model development, hyperparameter optimization, 5‑fold cross‑validation, and final prediction tasks. Users can directly run the provided model definition files (`CNN.py` or `Ankh.py`) to rebuild the network architectures and load trained weights to reproduce the reported results or perform batch predictions on new protein sequence embeddings or feature files.


Usage
==================
## Preparation

1. Download this repository, all the files are in the folder 'UBPs‑MFCPred'.

2. Users can directly run the `generateCMD-fold.py` script located in the `model` folder to automatically generate training commands for multi‑feature combinations across 5‑fold cross‑validation.

The script systematically enumerates all possible subsets of the seven feature types (CTriad, DC, Ankh, ESM‑1b, ESM2, PAAComp, ProtT5). For each subset (from single feature up to all seven features), it constructs a command that simultaneously uses:
• The raw protein sequences (one‑hot encoded) as a baseline feature,
• All selected PLM/traditional feature files from the corresponding fold,
• The corresponding neural network model files (e.g., `CNN.py` for raw sequences, and `CTriad.py`, `Ankh.py`, etc. for each selected feature).

Each feature combination is executed three times (`repeatTime = 3`) to ensure stability and reproducibility of the results. The script iterates over all 5 folds (fold0 … fold4) and all valid feature subset sizes.

All generated commands are printed to standard output and can be redirected to a batch script. The outputs, including prediction results, performance metrics, and training logs, are saved in structured directories (e.g., `tmpOut0/`, `tmpOut1/`, etc.) for further analysis and comparison.

Command:
>> python UBPs‑MFCPred\model\generateCMD-fold.py

Optimal Model Selection and Independent Testing

After completing the batch training process, users can analyze the results to identify the optimal feature combination and model configuration. The selected model can then be retrained on the full training set and evaluated on the independent test dataset to assess its generalization performance.

This workflow enables efficient and reproducible exploration of multi‑feature combinations, ensuring reliable model selection and robust performance evaluation.

==================
Optimal Model Selection and Independent Evaluation

During the model selection stage, all possible feature combinations (including single features and multi‑feature fusion) were systematically evaluated using a 5‑fold cross‑validation strategy on a training dataset consisting of 450 positive samples and 450 negative samples. For each feature type—including traditional encodings (CTriad, DC, PAAComp) and protein language model embeddings (ESM‑1b, ESM2, ProtT5, Ankh)—the corresponding neural network architecture was applied: the fixed CNN (defined in `CNN.py`) for all features except Ankh, and the DNN (defined in `Ankh.py`) for Ankh embeddings. Each feature combination was repeated three times to ensure stability. The optimal model configuration (i.e., the best performing feature set and its associated models) was identified based on average cross‑validation metrics such as accuracy, AUC, and F1 score.

After determining the best‑performing feature combination, the selected models (one per feature type within that combination) were retrained on the full training set and evaluated on an independent test dataset comprising 74 positive samples and 74 negative samples.

The evaluation can be performed using the following command (the feature files and model files should be adjusted according to the optimal combination identified):

>> python running.py --dataType protein other other other --dataEncodingType onehot other other other --spcLen 1000 200 200 200 --dataTrainFilePaths ./examples/UBPs‑MFCPred/data/train/potr.txt ./examples/UBPs‑MFCPred/data/train/netr.txt ./examples/UBPs‑MFCPred/data/train/potr_ESM1b.txt ./examples/UBPs‑MFCPred/data/train/netr_ESM1b.txt ./examples/UBPs‑MFCPred/data/train/potr_PAAComp.txt ./examples/UBPs‑MFCPred/data/train/netr_PAAComp.txt ./examples/UBPs‑MFCPred/data/train/potr_ProtT5.txt ./examples/UBPs‑MFCPred/data/train/netr_ProtT5.txt --dataTrainLabel 1 0 1 0 1 0 1 0 --dataTestFilePaths ./examples/UBPs‑MFCPred/data/test/pote.txt ./examples/UBPs‑MFCPred/data/test/nete.txt ./examples/UBPs‑MFCPred/data/test/pote_ESM1b.txt ./examples/UBPs‑MFCPred/data/test/nete_ESM1b.txt ./examples/UBPs‑MFCPred/data/test/pote_PAAComp.txt ./examples/UBPs‑MFCPred/data/test/nete_PAAComp.txt ./examples/UBPs‑MFCPred/data/test/pote_ProtT5.txt ./examples/UBPs‑MFCPred/data/test/nete_ProtT5.txt --dataTestLabel 1 0 1 0 1 0 1 0 --dataTrainModelInd 0 0 1 1 2 2 3 3 --dataTestModelInd 0 0 1 1 2 2 3 3 --outSaveFolderPath tmpOut --showFig False --saveFig True --figDPI 300 --savePrediction True --modelLoadFile examples/UBPs‑MFCPred/model/CNN.py ./examples/UBPs‑MFCPred/model/ESM1b.py ./examples/UBPs‑MFCPred/model/PAAComp.py ./examples/UBPs‑MFCPred/model/ProtT5.py --shuffleDataTrain True --batch_size 32 --epochs 25 --loss binary_crossentropy --optimizer optimizers.Adam(lr=0.0001,amsgrad=False,decay=False) --modelSaveName None --weightSaveName None --noGPU False --paraSaveName parameters.txt 

All prediction results, performance metrics, and related outputs are saved in the corresponding output directories for subsequent analysis and comparison.

This strategy ensures a clear separation between model selection and performance evaluation, while incorporating independence validation to enhance the reliability, robustness, and generalization ability of the proposed model.
